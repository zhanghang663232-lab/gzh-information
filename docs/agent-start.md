# 给豆包、DeepSeek、Codex 的 Mac v2 起步说明

本文件是**操作检查表**，不是“全量完成”声明。仓库默认 `main` 目前仍保留旧版 `wechat-archive`；当前 Mac 程序位于 `codex/v2-macos-validated` 分支。开始前先确认当前 README 第一行是 `# gzh-information v2`，并且根目录有 `安装.command`、`启动.command` 和 `src/gzh_reader/`。若只看到 `wechat-archive/scripts/archive_account.py`，你拿错了版本，先切换分支；不要索取 `down.mptext.top` API key 来替代当前路径。

用户此次要求豆包尝试**整个账号**时，直接按 [整账号执行入口](START-HERE-FULL-ACCOUNT.md) 的试跑与验收规则推进；确认单篇后运行不带篇数上限的持续读取。本页保留为通用起步检查表。

第一次接手先读 [构建复盘](build-history.md) 和 [故障手册](troubleshooting.md)。它们区分已确认的故障、仍未证实的原因和当前停止条件；不要只凭一份旧交接记录推断当前状态。

## 一次小批量验证

1. 在 Apple Silicon Mac 上确认桌面微信已登录。由用户在微信内打开目标公众号主页，并肉眼核对公众号名称。此步骤目前不能只凭一条链接全自动完成。
2. 从 v2 分支下载 ZIP 并解压到固定文件夹。双击 `安装.command`；安装成功后双击 `启动.command`。如果 macOS 要求“辅助功能”或“屏幕录制”权限，只给实际运行的终端/应用授权，之后重启它。
3. 在本地中文向导中填入**同一公众号**的一篇文章链接、主页显示的名称和输出目录。本轮最多新增先设为 **1 篇**；工作区累计保存上限可留空。首次试跑关闭模型复核与 Agent 模式，避免把模型连接问题混进桌面读取故障。
4. 运行期间让微信窗口保持可见，不要手动切换标签或遮挡公众号窗口。若出现登录失效、小程序授权弹窗、窗口识别不明或连续失败，停止本轮，保留运行状态供诊断；不要代用户点“允许”，也不要无限重试。
5. 检查输出目录下的 `audit/coverage.json`、`database/archive.sqlite3` 和文章正文文件。分别记录：本轮实际打开次数、新增的不同真实 URL 数、有效正文数、各互动字段有值数、缺失原因与停止原因。数字 `0` 是有效值，空值不是 `0`。只有明确列表末尾证据和覆盖率门槛都满足时，才可称“全量”。
6. 先核对 1 篇真实链接、正文来源、账号名和可见指标，再把可选篇数上限留空，持续读取同一账号。曾观察到长批次后微信退出登录；单篇或 10 篇成功不证明整号稳定。若退出登录，停止自动操作，先让用户恢复会话，再分析本轮证据。

## 模型的边界

DeepSeek、豆包 API 在此项目中是**可选的公开列表 OCR 复核/排序组件**，不是独立的电脑操作接口。点击、滚动、复制链接、身份核对仍由本机 `gzh_reader` 执行；仅配置模型 key 而没有本机 Mac 微信和权限，无法批量读取。首次验证不需要任何模型 key、导出服务 key、代理或本地 CA。模型 key 不得写入命令参数、日志、Git 或交接报告。

## 失败时先核对这四项

1. **版本**：是不是 v2 分支，而非默认 `main` 的旧脚本？旧脚本报“认证信息无效”不能证明 v2 失败。
2. **窗口**：Mac 微信是否已登录、目标公众号主页是否可见、应用权限是否生效？
3. **进度**：本轮停止原因是什么？打开次数增加但新增 URL 为 0，通常需要核对窗口/卡片身份与重复链接，不能继续盲点。
4. **数据**：文章正文成功、阅读数成功、分享数缺失、评论明细缺失是不同状态；不要互相代替或把缺失写成零。

提交问题时只提供程序版本/分支、脱敏后的状态和错误、窗口截图（先检查隐私）、`audit/coverage.json` 中的覆盖率与停止原因。不要提交 Cookie、API key、微信凭据、第三方文章全文或运行目录到 GitHub。

现有 [验收记录](acceptance/run-2026-09-27.md) 仅证实一个目标账号的 10 篇受限批次；换另一个公众号必须重新完成上述小批量验证。
