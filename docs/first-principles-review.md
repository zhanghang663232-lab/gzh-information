# 目标、证据与对抗式审查（2026-09-26）

## 唯一目标与当前里程碑

最终目标：只给一篇“监所家属”的文章链接，Mac 图形界面便能可恢复地读取该公众号普通用户可见的历史文章、正文和互动信息，明确列出拿不到的字段，并把不含账号隐私与采集数据的程序放进可复用的 GitHub 仓库。批量阶段可以使用低成本模型复核文字，但模型不能替代电脑窗口控制和保存结果的程序。

当前优先目标更小：从两个以上列表视口稳定取得至少 10 篇文章的真实链接、核对过的正文及可见指标；再次运行能续读；微信不退出登录；换一台干净 Mac 也能按图形向导重做。小样本通过之前，不称“全量成功”或“可复用完成”。

## 第一性原理

一条可信记录必须形成可检查的链条：目标账号主页 → 列表中的卡片 → 打开的文章标题与账号 → 真实链接 → 正文或指标的屏幕/复制证据 → 落盘文件 → 下次运行能识别同一篇文章。任一环缺失，只能记缺失，不能用 OCR 猜测或旧数据库 `ok` 代替。微信主页的“301 篇原创”是显示的总数，不是本程序已经枚举 301 篇的证明。

“稳定”不是单次复制成功，而是重复运行后同一动作能在窗口状态变化、滚动位置继承、弹窗出现时得到正确结果或安全停止。“全量”还要求列表末尾有明确完成证据；仅有 162 条本地记录不能证明文章全量。阅读、点赞、转发和评论是采集时的可见快照，不等于后台私有数据，也不能把不可见值写成 0。

## 对抗式审查：怎样推翻我们自己的乐观结论

1. “能复制文字”可能只是复制到标题、推荐卡片或页面局部。反证办法：抽样核对标题、账号、首尾段、长度和真实 URL；没有尾部证据就只标为最低长度通过。
2. “点击文章卡片”可能实际点到旧文章、小程序或微信其他窗口。反证办法：每次动作前后核对窗口/标签、标题和页面状态；意外弹窗立即停止，绝不自动允许。
3. “数据覆盖 100%”可能来自旧快照或错误占位。审计必须看每篇最新快照，保留真实数字 0，并区分字段可见性与质量等级。本次已修正旧快照重复计数。
4. “退出登录是微信风控”也可能是误关窗口、客户端崩溃或账号真正被踢。下一次只做小样本，留时间、动作轨迹、微信进程状态和可见提示；证据不足时不猜测原因，不通过换号/IP/设备规避平台限制。
5. “脚本在这台 Mac 上能跑”不等于别人能复用。必须从双击安装、粘贴链接、开始/继续、查看缺失清单走完一次干净安装验收；不要求使用者敲命令。

## 下一步实验顺序

1. **单篇修复验证**：在已登录微信中，从目标账号主页自动识别并读取一篇，确认页尾、关标签、回到主页；遇到小程序弹窗或身份不一致即停。不得用已有旧记录冒充新成功。
2. **两视口 10 篇**：每轮不超过 5 篇，先核对每篇真实 URL、正文首尾、可见指标，再做续传测试；若退出登录，记录确切症状并暂停自动化。
3. **验收与发布**：审计每层缺失原因和可见性边界，干净 Mac 双击复现后，再更新 GitHub 仓库和 PR 的“可复用”状态；之后才接入低成本模型做文字复核与扩大批量。

当前停止条件：实机单篇验收未通过，不能以“后台继续”为由运行新的大批量。已有数据保留，可随时重新审计。
