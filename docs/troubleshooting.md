# Mac v2 故障手册：供低成本模型逐项执行

更新：2026-09-27。本文只针对 `codex/v2-macos-validated` 分支的 **Mac 桌面微信界面采集**。`main/wechat-archive` 是旧版实验，使用另一条技术路线。完整决策来历见 [构建复盘](build-history.md)。本文件归纳已观察到的故障和可预见的失败模式；“可能原因”不是已证明的微信风控规则。

## 0. 每次运行只执行这套顺序

1. **核对版本**：根目录必须有 `安装.command`、`启动.command`、`src/gzh_reader/`；README 第一行是 `# gzh-information v2`。若当前程序要求 `down.mptext.top` 的 API key 或运行 `wechat-archive/scripts/archive_account.py`，先停止，切换到 v2 分支。
2. **核对目标**：记录用户提供的一篇文章链接、微信主页上肉眼可见的公众号名和输出目录。只采集同一个账号；账号名或文章标题冲突时停，不猜测。
3. **核对环境**：Apple Silicon Mac、桌面微信已登录、目标公众号主页可见；实际启动程序已获辅助功能和屏幕录制权限。权限“已授予”不代表微信画面实际可读；必要时运行 `gzh-reader doctor --visual`。
4. **先运行小批次**：图形向导本轮最多新增设为 1 或 5；首次关闭模型复核与 Agent 模式。程序默认每轮最多新增 5、硬上限 10，另有打开尝试上限。不要为了追求“全量”取消上限或自动连续重试。
5. **读真实结果**：打开次数、`new_in_run`、`stop_reason`、不同真实 URL、有效正文、五项互动数字、公开评论明细分别核对。进度条或主页“原创内容”总数都不是完成证明。
6. **遇到错误先停**：阅读下表的停止原因，再核对 `audit/human-agent-progress.json`、`audit/human-agent-last-error.json`、`audit/human-agent-action-trace.json` 和 `audit/coverage.json`。不要在未定位错误时重新启动相同批次。
7. **恢复时使用同一工作区**：已保存的正文应由 SQLite 和真实 URL 去重；再次采集新文章前重新观察当前微信窗口。更换公众号须使用独立工作区，不复用旧账号的卡片提示。

命令行仅作维护入口；普通用户优先双击 `安装.command`、`启动.command`，使用本地中文向导。维护入口：`gzh-reader doctor --visual`、`gzh-reader audit --workspace '<账号目录>'`、`gzh-reader resume --workspace '<账号目录>' --max-new-articles 5`。

## 1. 先按停止原因分流

| `stop_reason` 或现象 | 含义与下一步 | 可以直接重试吗？ |
| --- | --- | --- |
| `batch_new_limit` | 本轮新增上限已到。核对新增 URL、正文与字段后，才决定是否续采。 | 可以，使用同一工作区和小批次。 |
| `article_limit_reached` | 工作区累计保存上限已到；它不表示账号读完。 | 先核对上限设置。 |
| `batch_open_limit`，新增为 0 或很少 | 已到打开尝试上限。查是否重复打开旧文章、卡片标题与真实 URL 冲突、列表是否重排。 | 不要原样重试。 |
| `viewport_repeated_without_new_articles` | 视口重复且无新增；**不是**历史列表到末尾的证明。 | 先核对主页、滚动位置与列表加载。 |
| `wechat_login_required` | 微信明确要求重新登录。停止操作，由用户处理登录；不要自动尝试登录。 | 用户恢复并核对主页后再小批次。 |
| `wechat_session_unavailable`、`profile_lost_before_scroll`、`profile_restore_failed` | 无法证明当前窗口仍是目标公众号主页。 | 先让目标主页重新可见并核对。 |
| `ocr_unavailable`、`scroll_failed` | 截图/OCR 或滚动失败。查窗口可读性、权限、台前调度与具体错误阶段。 | 不要在未知窗口继续点击。 |
| `article_not_opened`、`link_copy_failed`、`body_missing`、`*_failed` | 单篇链路在对应阶段失败。读 `human-agent-last-error.json` 的 `step`；正文失败不能算新增成功。 | 先定位步骤，再做单篇复测。 |
| `link_title_conflict`、`account_mismatch`、`identity_recovery_limit` | 候选标题、真实链接或账号身份不一致。拒绝入库。 | 不要用旧坐标或旧链接提示强行续采。 |
| `agent_paused`、`agent_decision_failed` | 可选模型要求暂停或决策无效。先关闭 Agent 模式验证基础读取；模型不能替程序点击。 | 基础路径正常后再测模型。 |

即使程序显示 `incomplete`，也要看具体 `stop_reason`。它可能表示正常到达单轮上限，也可能表示窗口/文章失败。`complete=false` 是当前账号历史列表未获完整枚举证明，不是本轮所有正文都失败。

**10 篇限制的来源**：这是项目自行设置的单轮保护阈值，不是微信规定，也不是账号累计上限。图形向导和服务端限定 `max_new_articles` 为 1–10，采集器再次校验；默认 5。工作区累计上限是另一个可留空的 `max_articles`。到 `batch_new_limit` 后，确认微信仍正常、核对本轮真实 URL 与正文，再在同一工作区续采。既往约 30 篇后退出登录的观察尚不能证明具体触发阈值，因此不要把 10 当作“微信安全值”。

## 2. 已遇到的故障、证据与处理

| 场景 | 目前判断 | 低成本模型应执行的动作 |
| --- | --- | --- |
| 豆包从默认 `main` 运行 `wechat-archive`，收到“认证信息无效” | **已确认用错版本**。旧入口需要第三方导出服务 key；Mac v2 默认不需要。 | 先检查分支和根目录文件；切到 v2，按 [Agent 起步说明](agent-start.md) 操作。不要向用户索要导出服务 key 作为 v2 前提。 |
| 私有仓库 `git clone` 无凭据、`raw.githubusercontent.com` 超时 | 在豆包试跑中已观察；属于取代码阶段，不是微信采集故障。 | 用已登录的 GitHub 页面选择 v2 分支下载 ZIP；确认 ZIP 根目录有双击脚本和 `src/gzh_reader/`。不要逐个复制旧脚本拼装 v2。 |
| 旧版 `collect_articles.py` 抓到验证页或空标题 | 豆包报告的是旧下载器；不能由此推断 v2 桌面路径失败。 | 不把“换浏览器 UA”当作 v2 修复。核对实际运行的是桌面微信路径。 |
| 双击脚本打不开、`uv` 找不到、`ModuleNotFoundError: gzh_reader` | 旧安装/启动路径曾出现；现有源码体验包改为先安装固定依赖，再从本包的 Python 启动。 | 看 [Mac 安装说明](mac-delivery.md)；完整解压，先双击安装再双击启动。移动文件夹后重新安装；不要单独搬 `.venv`。 |
| `127.0.0.1:8765` 页面不动或启动第二个服务 | 可能是旧服务占用端口、任务已按上限停止或后台任务停滞；单凭页面不动无法判定。 | 看图形界面状态、`human-agent-progress.json` 的时间与停止原因；已有服务就使用原界面或正常停止旧服务，再启动一个。不要并行控制微信。 |
| 肉眼看到正常微信聊天，但程序 OCR 为 0 行 | **实机观察到**主聊天窗口系统共享状态为 0；屏幕录制权限检查可为真。公众号/文章子窗口曾可读。 | `doctor --visual` 实测目标子窗口 `capture_readable`；不可读就停止，不能因为权限绿灯或肉眼可见而盲点。 |
| 微信更新后公众号与聊天窗口合并/分开，文章成为标签 | **实机观察到**微信 4.1.x 窗口结构变化。 | 只用当次观察到的窗口、标题、账号名与标签；每篇后重新 OCR 主页。旧坐标、旧窗口号、旧标签数量不得跨步复用。 |
| 豆包 2026-09-27 在微信 4.x 搜索打开文章，窗口 `onscreen=false` | **其进度文件显示 0 篇入库、第一次 `copy_link` 失败**；报告中的固定坐标搜索和五个菜单候选点均未验证，`width-79` 已点到“向AI”。 | 不合入盲点/轮点补丁。先手动打开目标文章使窗口可见；新版程序会诊断不可见文章窗口并停止。可见文章仍须逐步核对标题、菜单和真实 URL。当前没有证据证明自动复制链接在该微信版本已修复。 |
| 同时存在多个同名“微信 (窗口)”或文章很长、账号名尚未出现在页尾 | 新报告提出多窗口与页尾缺失路径，但所附进度仍是同一次 0 篇、`copy_link` 失败；P0 说法缺少新的运行收据。代码已改为逐窗只读核对；仅唯一目标文章可被滚动到底部，再核对页尾入口。 | 不直接使用第一个同名窗口；不自动关闭错误页、不遍历猜测菜单坐标。若有多个目标文章窗口，先由用户保留一篇可见目标文章，再单篇复测。 |
| 已确认目标文章后，后续步骤又选到另一个同名窗口 | **已定位代码缺口并加保护**：确认文章时记住准确窗口号；复制链接、正文、页尾与关闭操作只使用这个可见且可截图的窗口。目标窗口消失时直接停止，不替换为第一个同名窗口。 | 先做单篇实机复测并核对真实 URL；窗口锁定有单元测试，但尚不能证明新版微信的菜单坐标正确。 |
| 多个同名窗口或多个文章标签的菜单识别失败 | 已加两道确定性保护：等待文章时只选择唯一包含目标标题/标签的可见窗口；菜单图像若识别出多个“…”按钮，只接受唯一属于目标文章标签的一个。无唯一证据就停止。 | 这解决的是“选错窗口/把多菜单当失败”的代码问题，不证明当前微信版本的图像识别已成功；仍须单篇验证菜单确实弹出“复制链接”。 |
| 台前调度把微信缩成侧边缩略图，后台控制报 `ax_unresolved` | **实机观察到**缩略图不可作为可靠卡片画面；关闭台前调度后，宿主机纯后台输入仍未通过。 | 当前路线要求可见微信窗口。不要把后台驱动能列举窗口当作能后台采集；也不要擅自修改用户系统设置。 |
| 2026-09-27 再次检查时仅看到台前调度缩略窗口 | 当前可见“微信 (窗口)”一度仅约 116×157；辅助功能 `Raise` 后截图仍为空白。后来通过微信菜单栏“窗口 → 微信 (窗口)”恢复了一个完整文章窗口，确认它是**无关公众号 Netskao**；连续点击时窗口又被台前调度移走，返回 `noWindowsAvailable`。因此**未验证目标账号的菜单复制或新采集**。 | 可以先通过微信“窗口”菜单恢复完整文章，再肉眼核对目标账号与标题；不要把缩略图、无关文章或一次成功截图当成稳定可控的批量会话。 |
| 打开卡片后出现“即将打开小程序／亲情邮” | **实机观察到**误点文章内卡片，说明当前页面或坐标已失效。 | 只取消弹窗；停止本轮，重新确认公众号主页并 OCR。不要点“允许”，不要沿用旧卡片坐标。 |
| 两个同名文章标签、菜单误点刷新按钮 | **实机观察到**慢加载与标签重排。当前实现按实际 OCR 的目标标签、菜单位置及正文标题核对。 | 未确认文章标题、圆形菜单属于目标标签时停止；不要从固定坐标猜菜单。 |
| 新文章沿用旧文章的靠下滚动位置，首屏字少 | **实机观察到**标题暂时不在视口或大图首屏文字稀少。 | 先确认目标文章标签和实际标题，再回顶部；不要只凭固定字符数判“未加载”。 |
| OCR 超时、`capture_start` 卡住、Vision/PyObjC 崩溃 | **已定位过本机程序问题**：主进程截图与后续子进程截图相互干扰；OCR 对象退出也曾崩溃。当前把截图和像素识别放入一次性子进程并设超时。 | 保存错误阶段与时间，不在长驻主进程重新加入直接 Quartz 截图；一次失败后按断点复核。 |
| 单篇失败后又关闭了一次窗口、误关主页 | **已定位并修复**外层重复关闭。 | 若仍出现，记录当时目标标签、前台窗口和动作追踪；不要额外发送 `Command-W` 试探。 |
| 旧卡片被重复打开，打开 3 次却新增 0 篇 | **实机观察到**；历史上受内部账号 ID、阅读数变化、候选排序及视口位置提示影响。 | 对比 `attempts` 与 `new_in_run`；已完成正文按真实 URL 去重。重复位置提示不是文章身份；到 `batch_open_limit` 后停并核对链接。 |
| 卡片“阅读3.8万 赞159 1个朋友转发”被读成点赞 1591 | **已定位并修复**：删除空格后数字粘连。 | 从原始 OCR 行解析并保留分隔；数字异常时对照卡片/页尾，不把异常值直接写成已核对指标。 |
| 页尾 OCR 把“阅读2706”误识为“阅读2706万” | **已观察并修正过一条数据**。 | 用同次卡片与页尾值做数量级核对；明显冲突时记录疑点，不凭单次 OCR 推算。 |
| 同一 URL 对应不同标题、不同公众号文章混入 | **已发现错误风险并加拒绝规则**。 | 停在 `link_title_conflict` 或账号冲突；核对真实微信 URL、标题和页尾账号。跨账号记录不得合并。 |
| 连续约 30 篇或更新后单篇即要求重新登录 | **用户多次观察，但触发原因未证实**。客户端崩溃、窗口误关、会话限制都需区分。 | 立即停；记最后成功篇数、最后动作、微信进程是否仍在、界面是否明确显示登录提示。不要换号、换 IP 或反复自动登录。10 篇成功不能推出长批次安全。 |
| DeepSeek/豆包 key 无效或模型不可用 | 适配器测试不等于真实连接；本机曾有格式无效的豆包密钥。 | 首次关闭模型仍应能运行基础路径；只有需要复核时再在图形界面临时输入有效 key 并点“测试模型连接”。不得把 key 写入 Git、聊天、命令参数。 |
| 分享数、旧点赞、评论明细没有采到 | **当前能力缺口**。10 篇实机样本阅读/点赞/评论计数各 10/10，分享数 0/10；旧点赞和评论明细未验收。 | 分字段记 `missing`，不能把空值当 0，也不能用评论计数冒充评论列表。 |
| 旧数据库有大量 URL，却没有有效正文 | **历史审计发现过**“只有链接却标正文 ok”的旧记录。 | 看正文文件和最新快照；只数经检查的有效正文。不要把 `articles_discovered`、旧 `content.ok` 或主页原创数当成功数。 |

历史细节见 [微信界面试跑](mac-ui-poc.md)、[退出登录排查](logout-investigation.md)、[2026-09-26 验收](acceptance/run-2026-09-26.md)、[2026-09-27 验收](acceptance/run-2026-09-27.md)。早期文档里的“尚未完成”是当时状态；以较新的验收记录和当前 `audit/` 为准，不把不同日期的数字直接相加。

## 3. 可能遇到但尚未证明的失败

- 列表永远显示同一视口、网络慢或底部信号不明确：停止并标记列表不完整；**重复视口不是末尾证据**。
- 微信升级后按钮、标签或公开数字布局改变：先采一张脱敏页面的布局证据，再修改解析规则；不能猜坐标或从图标旁的任意数字臆造分享数。
- 页面被删除、违规、限制访问，或普通用户看不到评论：分别写终态或缺失原因；不要生成空正文冒充成功。
- Mac 休眠、切换 Space、其他程序遮挡窗口：本轮可能失去可核对的目标窗口；恢复可见窗口并单篇复核后再续采。
- 新账号与旧工作区混用：即使两篇文章标题相同，也必须用真实 URL 和账号身份核验；不同公众号用不同工作区。
- 需要长期后台无人值守：当前宿主机路线需要可见微信窗口；独立 macOS VM 仍是未验收方案，见 [后台 Agent 路线](background-agent.md)。

## 4. 给下一位模型的交接格式

只提交脱敏的操作事实，按下面顺序填写；不知道就写“未知”，不要补猜：

```text
仓库分支/版本：
Mac 与微信版本：
目标公众号主页名称（已核对/未核对）：
本轮输出目录：
本轮打开次数 attempts：
本轮新增数 new_in_run：
stop_reason：
最后一个失败 step 与时间：
已核对不同 URL 数 / 有效正文数：
readNum / likeNum / oldLikeNum / shareNum / commentNum 各自有值数：
可见评论明细与回复数：
微信是否明确要求重新登录：
下一步唯一安全动作：
```

提交到 GitHub 的只应是脱敏故障描述和代码；运行目录中的文章正文、截图原件、聊天内容、Cookie、会话凭据、API key、代理状态不得提交。完成标准见 [可行性门槛](feasibility-gate.md)：小批量正文成功不等于账号全量，也不等于五项互动指标齐全。
