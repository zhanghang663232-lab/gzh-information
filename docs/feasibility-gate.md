# 单账号可复用采集：先验收小样本

目标不是先填满文章总数，而是证明同一套 Mac 电脑操作能从目标公众号重复获得可核对的数据，再扩大批量。当前只针对普通用户可见的公开内容；未展示或后台私有数据不得写成零。

## 小样本通过条件

1. 从公众号主页自动发现至少 10 篇、跨至少 2 个列表视口的文章；每篇都能核对公众号身份、文章标题和真实 URL。
2. 至少 10 篇保存有效正文及来源证据；阅读、点赞、转发、评论计数逐字段记录可见值或明确的缺失原因。可见评论与回复另行记录，不把评论计数当作评论明细。
3. 第二次运行只续读缺失项，不重复覆盖已成功正文；微信保持登录。任一文章卡在打开、复制、正文或评论步骤时，停止本轮并留下步骤证据，不连续盲点。
4. 在干净安装环境重复上述过程后，才把 GitHub 工作流标记为可复用；低成本模型只能替换文字识别/复核层，不能替代窗口控制与结果校验。

## 2026-09-23 当前证据

- 微信主页显示 301 篇原创内容；这不是已发现文章列表的完成信号。
- 重新核对本地 162 条文章记录的最新正文文件：数据库曾把 155 篇标为 `ok`，但只有 43 篇通过“非 URL 文字至少 80 字”的最低检查；112 篇为误标，其中 110 篇文件仅有 URL。43 篇仍未逐篇验证首尾段与完整性。
- 2026-09-26 重新审计每篇**最新快照**的非空指标：阅读 162、点赞 162、转发 1、评论计数 73、旧点赞 0。先前“转发 4”包含旧快照值，不能代表当前覆盖。数字 0 是有效观测值；非空也不代表人工核对无误；评论明细 0。
- 新版微信会沿用旧文章的滚动位置；实机确认目标文章已在标签中打开，但页面位于底部，导致旧版错误报告“文章未打开”。将滚动条拖回顶部后，目标标题和正文均可确认；该恢复步骤已写入状态机。
- 单篇实机试验已通过“打开目标文章 → 复制真实链接 → 复制有效正文”，但在读取页尾时因页尾文字太少，被顶部文字门槛误判为“尚未加载”，所以该次没有入库。页尾现独立核对窗口编号，不再沿用顶部文字门槛；尚需单篇复验。
- 上次失败后程序又打开了第二篇，违背了本文件的停止条件。现在任一文章采集步骤失败即停止本轮；公众号标签前出现 OCR 字符 `X` 时也可准确切回主页。修正后 71 个测试通过，但没有再启动批量。

当时结论（2026-09-23）：未通过小样本端到端验收，不运行批量，也不宣称全量或可复用。后续结果见下方更新。

## 2026-09-27 更新

目标账号主页显示 302 篇原创内容。桌面微信路径先后完成 1 篇、3 篇、5 篇受限批次；随后单轮 10 次打开均得到不同真实 URL 和有效正文文件，工作区可核查正文累计 66 篇。整个 10 篇批次未观察到退出登录。故本文件条件 1 和条件 2 的“自动发现、真实链接、最低正文检查”部分通过；条件 3 的断点续传已在多轮试跑中工作，但长时间全量和干净安装环境实机重复仍未验收。完整证据见 [run-2026-09-27.md](acceptance/run-2026-09-27.md)。

该批次 `readNum`、`likeNum`、`commentNum` 各 10/10 有值，`shareNum` 为 0/10 有值（全部明确记为缺失），`oldLikeNum` 和可见评论明细未完成。因而**不能**把“正文小样本通过”写成“五项互动指标通过”或“整个账号全量通过”。

目标、证据分层和反证实验见 [first-principles-review.md](first-principles-review.md)。
