# 给豆包的独立执行稿：启动本机程序读取整账号

把本页当作**执行说明**，不要把“我不能亲自点击 Mac 微信”当作任务结论。本仓库不要求豆包聊天窗口点击微信：`gzh-reader` 是安装在这台 Mac 上的执行器，负责可见微信窗口的观察、点击、复制、核对和断点保存；豆包只负责启动执行器、检查状态、定位故障。豆包 API 可选，只做公开列表 OCR 复核/排序；**豆包 App、本机执行器、豆包 API 是三个不同东西**。

## 第一关：先检查你能做什么

1. 如果当前豆包会话有**本机命令/终端执行工具**，用它进入本仓库，读取 `AGENTS.md`，确认分支为 `codex/v2-macos-validated`，运行 `.venv/bin/gzh-reader --help`。只调用允许的本机工具，不要声称自己亲自操作微信，也不要通过浏览器打开公众号网站代替桌面路径。
2. 如果只能读写本地文件、不能运行本机命令，明确说“当前会话缺少本机命令执行能力”，请用户**双击本仓库的 `启动.command`**；然后从本地向导开始或检查已有工作区的审计文件。不要反复回答“我不能操作微信”，因为点击本来是执行器的工作。
3. 如果既不能运行本机命令，也不能读取本地工作区，明确说当前会话无法监督采集，并列出缺少哪两项能力。不要假装已启动、换网页路径、编造进度或要求用户交出微信凭据。任何工具明确禁止启动本机执行器时，尊重该限制并停止，不尝试规避。

## 第二关：核对目标和工作区

本次示例账号是 `Netskao`，起始文章链接是 `https://mp.weixin.qq.com/s/cleXgWkz9UlinSLeQdLefQ`。用户可替换为其他公开公众号，届时要用该账号独立工作区。现有 Netskao 工作区已有 **1 篇**通过最低正文检查；这不是整号完成证明。不要假设工作区就在仓库目录，更不要新建第二份 `Netskao/` 来掩盖旧失败。先从已给的工作区路径或本机文件查找 `Netskao/database/archive.sqlite3`，再确认同目录有 `audit/human-agent-progress.json`，且账号名称一致；存在多个候选就停止询问确切路径。

当前已知第二篇曾卡在 `account_mismatch`、`copy_link_failed` 和 `profile_restore_failed`。微信 4.x 的窄标签可能隐藏文章菜单；执行器在不能唯一确认菜单时会停，不应让模型猜坐标。

## 第三关：本机命令可用时直接执行

以下 `<仓库目录>` 和 `<已有工作区>` 必须替换成**本机已核对的绝对路径**，不要原样提交尖括号。先确认没有另一采集进程控制微信，并检查窗口诊断：

```bash
cd '<仓库目录>'
.venv/bin/gzh-reader doctor --visual
.venv/bin/gzh-reader audit --workspace '<已有工作区>'
```

只有桌面微信已登录、目标公众号主页可见且身份可核对，才先用同一工作区做一次有界复测（上轮第二篇失败，不能跳过这道门）：

```bash
.venv/bin/gzh-reader resume --workspace '<已有工作区>' --max-new-articles 1
```

核对本轮确实新增一个**不同的真实文章 URL**、正文首尾可抽查、账号名正确、微信未退出登录后，直接执行整账号持续读取命令；**不加两个篇数上限**，无需每 10 篇手动重启：

```bash
.venv/bin/gzh-reader resume --workspace '<已有工作区>'
```

让命令在本机可见会话中运行，微信窗口保持可见。程序每 10 篇更新导出与审计，但不会因 10 篇自动结束；每篇落入同一 SQLite 断点。不要并发启动第二个采集器，不要关闭未知微信窗口、自动重新登录、切换代理或轮换账号/IP。用户手动停止或程序异常停下后，**先看停止原因**，不要无条件重复 `resume`。

## 第四关：读结果，不要把“命令退出”叫全量

检查 `<已有工作区>/audit/human-agent-progress.json`、`human-agent-last-error.json`、`human-agent-action-trace.json`、`coverage.json`。至少报告：本轮打开次数、本轮新增数、累计不同 URL 数、正文有效数、`stop_reason`、五个指标各自有值/零/缺失数、评论明细状态。数字 `0` 与缺失不同；“1 个朋友转发”不是总分享数。

- `batch_new_limit`：只有显式设置了试跑篇数上限才正常出现；它不是整账号完成。
- `link_copy_failed`、`account_mismatch`、`profile_restore_failed`、`wechat_login_required`、窗口不可读、小程序弹窗：停止当前尝试，查 [故障总账](incident-ledger.md) 和 [故障手册](troubleshooting.md)，提交脱敏收据；不要盲点或无限重试。
- `scroll_failed`、`viewport_repeated_without_new_articles`：也不能单独证明历史列表已到末尾。当前程序可能保持 `complete=false`；不得因为主页写着 1271 篇或 SQLite 数量接近它就声称全量。

只有完整列表末尾证据、正文覆盖率、五个指标逐字段覆盖率、可见评论明细状态和缺失清单都经过审计，才报告“全量”。否则报告**已保存的实际篇数和下一处卡点**。仓库不上传数据库、文章正文、截图原件、聊天、Cookie 或 API key。

## 直接发给豆包的一句话

> 请按本页第一关检查你是否能运行本机命令。不要尝试亲自点击 Mac 微信，也不要仅因不能点击微信就拒绝任务：本机 `gzh-reader` 负责点击，你负责启动它并监督审计。若没有本机命令执行工具，请准确告知缺少的能力并让我双击 `启动.command`；若能执行，则使用现有 Netskao 工作区先复测 1 篇，成功后不设篇数上限持续读取。任何失败给出真实 `stop_reason`，不要宣称已全量。
