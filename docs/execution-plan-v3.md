## 1. 产品目标与两次交付

最终产品：用户双击启动，粘贴目标账号的一篇文章链接，选择读取范围和模型，自动读取同一公众号的文章正文、公开可见互动与评论，支持暂停、恢复、导出。Mac 执行界面操作；DeepSeek、火山方舟豆包及 Codex 共用一套本地工具。

第一次交付是经过实机验证的小批量预览版：新采集 10 篇、至少两个列表视口、身份和正文可核对、能恢复任务、两个供应商的真实 Agent 路径分别通过测试，然后同步到用户的专用 GitHub 仓库。第二次交付是经过超过历史约 30 篇故障点的批量版本，目标首轮 50 篇，再支持指定总数或读取到可证实的末尾。10 篇是验证步骤，不是产品上限。

数据范围：标题、作者、发布时间、文章链接、正文，页面可见阅读、点赞、在看/推荐、转发、评论数，以及可见评论、回复、互动数和资源引用。所有不可见或未取得的字段列明缺失。纯界面路线若无法取得某必需字段，必须报告能力缺口，不能把“未取得”改成“全量成功”。

## 3. 第一性原理与架构

可信记录需要连续证据：正确账号 → 正确卡片 → 正确文章 → 本篇来源链接 → 实际正文/可见数字 → 文件与数据库提交 → 恢复时识别为同一篇。

稳定批量等于“单篇正确执行器 + 持久队列 + 有界恢复”。模型负责从程序提供的合法动作中选择；程序负责窗口、坐标、动作前置条件、数据校验、写入和结果判定。

```text
中文向导 / Codex MCP 客户端
              ↓
固定调度 或 DeepSeek/豆包 Agent runtime
              ↓ 同一套有类型的工具
单实例任务队列 → 观察与状态机 → Mac 微信控制器
              ↓
身份核验 → 正文/指标/评论独立提交 → SQLite + 原始证据
              ↓
恢复 / 覆盖率审计 / Markdown、JSONL、CSV 导出
```

本地 FastAPI 只用于界面和任务控制，不等于调用微信公众号后台接口。采集路径不依赖已下线的导出网站。模型 API 用于决策，归档与界面控制在 Mac 完成。

普通文字模型无需原生 Computer Use：它调用 `open_article(candidate_id)`，本地工具完成实际点击。模型需要可靠输出工具调用或规定 JSON；支持视觉的模型可选用目标区域截图，但视觉不是基础依赖。豆包 API 接入不等于控制豆包聊天应用。

## 4. 执行契约：低成本模型只做有限决策

### 4.1 工具

| 工具 | 前置状态 | 结果与强制校验 |
| --- | --- | --- |
| `observe()` | 任意 | 当前页面类型、观察 ID、可用动作；不产生点击 |
| `resolve_account(seed_url)` | 画面可读且微信登录 | 从真实页面建立账号身份；不依赖聊天中预先存在链接 |
| `list_candidates()` | 账号主页已确认 | 当前视口的候选 ID、标题、位置引用、已知状态 |
| `open_article(candidate_id, observation_id)` | 当前主页、观察仍有效 | 打开后验证标题、账号、URL；过期观察拒绝执行 |
| `read_article()` | 文章身份确定 | 完整性结果及已提交正文的回执 |
| `read_visible_interactions()` | 本篇文章仍有效 | 逐字段快照、评论/回复及明确缺失原因 |
| `return_to_profile()` | 已知文章/明确可取消弹窗 | 核对返回后的账号和列表；失败暂停 |
| `scroll_list(observation_id)` | 主页已确认 | 新视口及新观察 ID；未变化不推断到末尾 |
| `pause(reason)` | 任意 | 保存任务状态，释放控制权 |
| `get_progress()` / `export()` | 任务已创建 | 返回真实数据库结果，不让模型自行宣布成功 |

界面动作必须单线程、单一控制者；GUI、CLI、MCP 使用同一个任务锁。重复调用有请求 ID；不盲目重放点击。模型决策期间窗口一旦变化，原观察立即过期。

每次返回固定结构：

```json
{
  "task_id": "run-001",
  "observation_id": "obs-017",
  "state": "profile_ready",
  "allowed_actions": ["open_article", "scroll_list", "pause"],
  "candidates": [{"id": "card-004", "title": "公开文章标题", "status": "pending"}],
  "evidence_refs": ["local:evidence/017"],
  "error_code": null,
  "retryable": false
}
```

候选 ID 仅在本次观察中有效。文章 URL 建立后分配持久 article_id。工具参数通过结构校验后还必须通过状态、窗口焦点、账号、当前视口校验。模型不得传任意坐标、shell、代码或目标账号以外 URL；正文与 OCR 中的指令视为数据。

### 4.2 预算与恢复

普通已识别页面采用固定流程可实现零模型调用。Agent 模式每个稳定状态最多一次决策，格式错误最多一次修正；持续无效则暂停。每次只发送当前状态、允许动作和必要候选文字，不携带整段会话或整篇正文。

初始工程超时：截图/OCR 10 秒，单个窗口动作 15 秒，页面加载 30 秒，模型请求 20 秒；正文滚动等长任务有持续进展事件和独立总上限。全部可配置，实测后调整。这些是防卡死参数，不是微信安全阈值。

分别检测进程存活与业务进展；心跳正常但卡片、滚动、正文覆盖连续无变化也须暂停。不能仅凭循环不断发日志就认为有进展。现有 120 秒无事件停止只作为最后一道保护。

## 5. 按依赖顺序执行的工作包

每个包内部也只做一个可核验变更后再继续。已有模块逐步提取和替换，保留当前数据与可工作的函数。

### W00：固定事实、任务与旧数据

输入：当前仓库、测试结果、现有工作区。

动作：记录 Git 提交/工作区差异、Mac/微信版本、窗口布局、显示器缩放与权限；只读审计旧数据。建立 `docs/acceptance/` 和本地 `audit/runs/`，区分计划、代码完成、模拟通过、实机通过。正文旧成功标记增加可追溯的质量复核，不删除旧快照。

产物：基线清单、历史故障表、编号任务卡。每个旧故障必须有回归样本或明确的待取证项。

通过：任何后续模型只读仓库即可知道下一张任务卡及证据，不依赖本聊天。

### W01：让程序确实看得到页面——当前首要阻塞

目标模块：`ui/observer.py`、诊断入口、向导。

动作：将“权限已授予”和“实际可取得图像/文字”拆成两项。先用本地可控测试窗口显示固定文字，验证截图与 OCR，再验证微信窗口。记录截图尺寸、窗口/显示器 ID、内容变化、OCR 行数、前台状态；空白判定组合多个信号，不能用低图像方差一刀切正常空白页。

按顺序排查：屏幕锁定/休眠、当前用户会话、实际运行进程的权限、窗口位于哪个空间/显示器、截图方式兼容性。截图不可用时尝试经过测试的替代捕获方式，或在辅助功能能提供所需信息时使用该信息；更换捕获技术需独立实测。台前调度先采用明确、可复现的一种配置记录基线，不把它预设为根因。

通过：校准文字可读，微信目标主页关键文字可读；移动窗口后仍定位正确。失败显示“画面不可读”，不推断账号退出，不触发采集动作。

### W02：只给一条链接也能进入正确账号

目标模块：`ui/bootstrap.py`、`ui/layouts.py`、向导预检。

动作：验证 URL 为微信文章链接；优先复用已经打开且核验一致的文章/主页。没有则通过已验证的微信界面入口打开种子链接。若该版本只能借助文件传输助手，设计一次性设置与明确的仅向自身发送公开链接步骤，不能依赖历史聊天恰好含链接，也不能向任意联系人发送。尚未找到可行入口时，由向导引导一次手动打开，标记为“入口半自动”，不宣称纯一键完成。

从种子文章建立身份锚点，再点击发布账号进入主页，核对账号标识、名称与页面来源。标题/名称不唯一；短链与长链的合并须有真实页面依据。取得 `__biz` 等稳定标识时使用，未取得则保留待确认身份，禁止只凭同名跨目录合并。

通过：冷启动、只开聊天窗口、已有文章三种场景都得到正确主页或明确可操作提示；不能误入“安徽监狱”等其他账号。

若仍需手动打开种子文章，可继续做单篇执行器的局部实验，但 W02 的“一条链接自动进入账号”子项保持未通过；正式交付不能把这一步悄悄变成用户长期必做操作。

### W03：适配新版微信布局和弹窗

目标模块：`ui/layouts.py`、`ui/controller.py`，逐步减少大文件中的布局判断。

动作：分别实现独立公众号窗口和合并标签布局，以实际控件/页面识别选择适配器。坐标从当前窗口、缩放和 OCR/辅助功能元素计算；页面变化后重取。点击后必须验证结果。关闭优先针对已确认的文章标签；全局快捷键只有验证焦点后可用。

小程序弹窗只能在识别出弹窗和“取消”后取消，再观察。一次失败即暂停；当前文章不盲目重开。继承滚动位置时先识别文章，再恢复顶部；页尾采用独立判断。外部抢占窗口、未知弹窗、身份不明时暂停。

通过：两个布局、窗口移动/缩放、文章从底部打开、小程序弹窗、用户切换窗口都能正确处理或有界停止。支持矩阵按实测填写，未测布局标未验收。

### W04：单篇正文闭环与分阶段提交

目标模块：`workflow.py`、`content_quality.py`、`storage.py`。

顺序：主页 → 选择候选 → 打开 → 核对账号/标题/URL → 读取正文 → 校验 → 保存正文 → 读取互动 → 返回主页并核对。

复制前设任务专用剪贴板标记，复制后验证内容确实变化且属于当前文章，任务结束在不覆盖用户新剪贴板的前提下恢复。正文校验包含身份、标题、开头、结尾与提取覆盖；最低 80 字仅作异常提示，不能作为完整标准。文字短文、图片正文、删文各有独立类型。

正文按页面可复制文字优先；无法完整复制时才采用分段滚动提取，保存每段位置、重叠和拼接证据。不能可靠重建则记 partial，不把 OCR 猜测当原文。图片正文先列资源和可见文本，专门样本验收后才计入相应类型成功。

原始文件先原子落盘，计算校验和，再以 SQLite 事务写入引用。正文成功后即提交，不等待指标或评论全部成功。后续失败可单独补采。

通过：三种长度/起始滚动位置的文章完成循环；核对真实 URL、账号、正文首尾与内容覆盖。注入页尾失败后正文仍可读、仍有正确来源。

### W05：逐字段互动、评论和回复

目标模块：`interactions.py`、`comments.py`、导出与审计。

动作：保存每个指标的页面原标签、原字符串、可解析值/范围、时间、证据及状态。不同版本的爱心、推荐、在看等图标单独建立实测映射；不能只看位置塞入 `likeNum/oldLikeNum`。未建立映射时保留原标签，标记语义待核对。

0 是真实值；“1万+”“10万+”保存为有下界的显示值，不能导出成精确整数。阅读量不一定在文章页尾，来源若是列表需记录来源，且不能与另一篇混合。

评论按可见入口展开、滚动、展开回复，保存可见标识/作者显示名/文字/时间/点赞/父评论关系/资源引用及观察位置。没有稳定评论 ID 时采用明确的保守合并策略，保留来源，不凭相同作者和文字强行合并。

分别标记：明确无评论、未开启、公开列表末尾已到、仅已加载部分、加载失败、不可见。未看到评论不能写成“0 条”。普通用户未展示的评论不计入可收集范围。

通过：至少一篇有可见评论及回复、一篇明确无评论/关闭评论样本；可见字段逐项人工核对。如果目标账号没有某类样本，可用第二个明确指定的公开测试账号分库存放，该字段在目标账号仍标未验证。

### W06：队列、去重、续传和进程故障恢复

目标模块：`scheduler.py`、存储迁移、`task_worker.py`、`web.py`。

数据库持久化任务目标、文章阶段、列表锚点、最后有效观察、尝试记录、暂停原因、模型配置引用；密钥不随任务落盘。发现阶段先存 provisional candidate，拿到真实 URL 后再确认唯一键。标题与阅读数只能辅助定位，不能是最终去重键。

恢复时先观察并核对账号，再定位保存的列表锚点；有限回退扫描，记录已扫描视口和重复打开数。已完成正文跳过，指标按用户选择刷新，缺失评论单独重试。旧账号别名合并需要来源证据；名称相同不是充分条件。

只有一个进程持有 Mac 输入锁；GUI/CLI/MCP 不能同时操控。任务停止先取消/等待在途动作，再释放锁；强制终止后重新进入观察状态，不重放上次点击。重启后处理事务中断与孤立临时文件。

通过：分别在打开后、正文提交后、评论中、返回前中断再恢复；成功正文不覆盖、不重复归档，不把旧正文绑定到新 URL。界面和服务重启后能恢复真实任务状态。

### W07：退出登录的逐动作诊断

目标模块：`diagnostics.py`、动作事件与验收报告。

依赖 W00/W01，随后贯穿所有实机步骤；任何一步出现退出即可进入本包，不要求先通过 W04–W06。

分类至少包括：明确重新登录提示、微信进程崩溃、窗口误关闭、窗口隐藏/切换空间、截图不可用、页面超时。保留动作开始/结束时间、进程 PID/变化、窗口 ID、最后成功文章、精简局部证据；不上传完整聊天。

实验顺序：人工打开同一类文章基线 → 自动观察 → 自动打开一篇 → 加正文复制 → 加页尾滚动 → 加返回 → 加下一篇。每轮只增加一个环节；重复使用相同环境配置；先测试能复现的本地问题。出现明确退出/崩溃立即结束本轮并留下记录，不通过不停重登来找阈值。

定位窗口关闭问题则改焦点/关闭逻辑；定位崩溃则核对调用与崩溃栈并替换相关操作；只有明确会话提示才能记录会话失效。无法确定因果就标未定位。固定慢速不是已验证修复，随机延时或“像人”不能作为验收依据。

通过：已知本地故障有修复及反证测试；稳定性在后面的持续 50 篇和第二次续采中观察。即使通过，也只能说明该版本/环境/样本通过，不能承诺永不退出。

### W08：DeepSeek 与豆包共用的真正 Agent

目标模块：`models/`、`tool_schema.py`、`agent_runtime.py`、向导连接测试。现有两个客户端与卡片排序 Agent 逐步迁移，保持旧配置兼容。

配置：供应商、base_url、model_id、密钥引用、tool calling/JSON 模式、超时、调用预算、可选视觉。模型 ID 来自用户实际开通服务和连接验证，不能把当前代码的默认 ID 当成永远存在。供应商特有 thinking/response_format 参数由适配器处理。

工具循环：观察 → 构造精简状态 → 模型选择 → schema/状态校验 → 本地工具执行 → 新观察和回执返回模型 → 下一步。一次循环只执行一个会改变界面的动作。支持原生 tool calling；不支持者用同一 schema 的 JSON 动作，非法输出不执行。

模型能力测试分四层：认证成功、格式/工具协议成功、模拟流程成功、实机任务成功。计费 token 与调用量由返回值和本地计数记录；预算耗尽保存断点。

通过：DeepSeek、豆包各用真实 API 完成至少 3 篇经核对的实机文章，并在暂停后切换供应商接续同一任务；新增工作可纳入总体验收样本。不得仅因返回 `{"ok":true}` 或给卡片排序就标“Agent 已接入完成”。

### W09：10 篇小批量验收与 GitHub 预览版

依赖：W01–W08 的相应路径通过。先固定流程 1 → 3 → 10 篇，至少两个列表视口，再核对两个模型路径及交叉恢复。

10 篇全部核对身份/URL/正文；当时可见的目标指标逐字段核对；没有可见值的字段有明确原因。评论路径用 W05 样本单独验证。包括主动暂停、重启、重复启动拒绝和切换模型。实机不能以旧库存冒充新采集。

通过后同步用户专用 GitHub 仓库，标记预览版本和真实支持范围。尚未通过的字段/布局明确列出；不能宣称账号全量，也不必等整个账号读完才发布经过验证的代码。核对远端仓库归属；如已有 `gzh-information` 则复用，避免继续建重名仓库。

### W10：持续批量与列表完整性

用户的“读取数量”改为三种清晰模式：本次新增 N 篇、达到总计 N 篇、读取到可确认的列表末尾。内部检查点批次与用户总目标独立；正常小批次完成后自动继续，避免每 5 篇都要用户点击。

先做一个累计 50 篇的任务，跨过曾报告约 30 篇的问题区间；中途检查点不能自动重登或通过人为重启规避验证。再做第二次恢复/增量任务。记录新保存数、重复打开数、卡住次数、退出/崩溃次数、完整性、耗时和模型消耗。

完成条件分别是：达到用户设定数量，或明确末尾提示且加载完成并复核末尾视口。重复画面只能作为暂停/检查信号；没有明确末尾证据时写 `list_incomplete`。主页原创数不是所有历史文章数，不能用相等数字证明全量。

通过：50 篇身份与数据检查通过、任务能够自动跨内部批次继续、期间无会话退出/客户端崩溃；第二次恢复不重采成功正文。无法通过则回到对应故障包，不继续扩大规模。

### W11：安装、GUI、MCP 与正式交付

GUI：粘贴链接 → 确认账号与读取范围 → 选择固定流程/DeepSeek/豆包 → 开始 → 中文阶段进度 → 暂停/继续/打开结果。模型设置折叠；日常使用不要求终端。显示完整正文数、部分正文数、字段缺失、发现数量与列表是否已枚举完，避免单一虚假完成百分比。

密钥由本地隐藏输入提供，可选择 macOS Keychain 保存；本地服务绑定 loopback 并校验调用者，任意网页不能启动鼠标操作。模型默认只接收必要公开列表文字；向模型发送截图需明确设置且限目标区域。

外部 Agent 使用相同工具的 MCP 适配层；Codex 为宿主，DeepSeek/豆包 API 在仓库 Agent runtime 中运行，两者职责写清。多入口共用任务锁和存储。

打包保留双击安装/启动入口，测试 wheel 安装后从仓库外启动，避免再次 `ModuleNotFoundError`。在干净环境检查 Python、依赖、权限、微信布局和可读画面；模型 API 非必要依赖，固定流程能独立运行。CI 运行离线协议/存储/状态测试，不能冒充真实微信 UI 验收。

正式一键流程必须验证：微信已登录且权限已设置时，只在本应用粘贴种子链接即可进入目标账号，无须预先在聊天里准备链接或手动切到主页。做不到时明确保留半自动版本，不声称这一需求已实现。

交付内容：源代码、依赖锁、中文使用手册、模型配置说明、MCP 配置示例、脱敏回归样本、已验证兼容矩阵、验收报告。运行正文、个人截图、密钥和会话数据不提交 Git。保持独立实现，不复制参考项目受不同许可证约束的代码。

## 6. 数据与状态约定

正文、指标、评论各有独立采集状态，并另设质量字段。例如正文 `status=ok` 只说明操作成功，只有 `quality=verified_complete` 才计入完整正文；`partial`、`unverified` 分别显示。任务状态采用 queued/running/paused/needs_user/completed/failed，不与文章字段状态混用。

每个指标记录 source、captured_at、raw_label、raw_value、parsed_value 或范围、status、missing_reason、evidence_ref。评论列表另记 enumeration_status，区别“保存了一些评论”与“该页面公开评论已到末尾”。

导出：SQLite、JSONL、文章 CSV、指标快照 CSV、评论及回复表、Markdown/Obsidian 首页和文章、缺失清单、SHA-256 清单。Obsidian 首页用公众号名称作一级标题。目录名称不承担账号身份校验。

恢复检查点包含 account_id、seed_url、article_id、内容/指标/评论阶段、list_anchor、pending_candidates、last_event_id、stop_reason、layout_version、model_config_ref。凭据不写检查点。原始采集证据只保留任务所需公开页面区域。

## 7. 对抗式验收：主动推翻错误成功

| 要推翻的假结论 | 反证测试 | 正确结果 |
| --- | --- | --- |
| 权限全绿等于可读取 | 权限正常但返回白图 | 停在画面诊断，无点击 |
| 模型说打开即打开 | 执行后仍在旧标签 | 不读取/保存成新文章 |
| 复制成功等于正文完整 | URL-only、旧剪贴板、局部选区、短文/图片文 | 分类并保留证据，不能只按长度判完整 |
| 同名就是同一账号 | 同名账号/跨账号文章 | 拒绝错误归属或待核对 |
| 出现数字即字段正确 | 图标换位、推荐与点赞混淆、1万+ | 保留标签和范围，不伪造语义/精度 |
| 进程活着就是在前进 | 持续心跳但重复视口 | 业务无进展触发暂停 |
| 两个执行入口都能启动 | GUI 与 MCP 同时启动 | 第二个被锁拒绝 |
| API 接通就是完整 Agent | 合法 JSON 但过期候选/非法动作 | 执行器拒绝并回传实际状态 |
| 10 篇成功就是稳定全量 | 50 篇任务与恢复任务 | 独立批量报告；样本成功与列表完成分开 |
| 测试数增加即项目完成 | 无实机单篇报告 | 里程碑仍为待实机验证 |

## 8. 给低成本开发 Agent 的任务卡

每张任务卡必须包含：ID、依赖、现有文件、具体症状、最小复现、允许修改范围、期望行为、禁止回归、验证方式、实机证据要求、停止条件和下一任务。一次只领取一张；中断后从任务卡和数据库恢复。

```text
任务：W01-01 画面可用性诊断
前置：读取本计划和当前 observer/ocr/doctor 实现。
症状：权限报告正常，但微信 OCR 0 行，其他应用截图也为白色。
范围：诊断模块、中文诊断提示、对应故障测试。
要求：分别报告权限、捕获、OCR；失败不能进入点击步骤。
验证：可控测试窗口有字/白图/捕获超时；真实微信页面另行验收。
完成记录：变更文件、测试结果、实机证据引用、尚未证明的事项。
下一步：只有可读画面实机通过才进入 W02 的自动导航试验。
```

运行模型的简明规则：只从 allowed_actions 选择；只使用本次候选 ID；观察失效先 observe；错误不改写为成功；保存成功由工具回执证明；达到目标或工具要求暂停即停止；模型不能代替本地程序宣布完整性。

## 9. 执行顺序和发布门槛

主线：`W00 → W01 → W02 → W03 → W04 → W05 → W06 → W08 → W09 → W10 → W11`。W07 在 W01 后启用，并贯穿每个实机阶段；模型接口的离线开发不依赖窗口恢复，但真实模型采集验收依赖稳定单篇工具。

模型协议和离线回归可在等待实机环境恢复时推进；画面不可读时不进行依赖视觉的线上点击验收。GitHub 预览版在 W09；批量正式标记在 W10/W11。任何阶段失败都回到具体失败工作包，不重写整个项目、不累加无证据的成功承诺。

下一次具体执行：固定基线 → 校准窗口/微信真实画面检测 → 进入正确主页 → 新采一篇并分阶段保存 → 核对返回主页；在这个链路通过前，不扩批。
