# Mac 微信界面采集试跑记录

更新：2026-09-23。这里仅记录采集能力和缺口，不包含文章正文或用户凭据。

## 已验证的链路

1. 人在 Mac 微信打开目标公众号主页，程序用窗口标题和主页 OCR 核对账号。
2. 程序识别历史文章卡片，模拟点击，复制微信内置文章窗口中的真实链接与可选择正文。
3. 打开文章底部核对公众号名称；不一致时拒绝入库。
4. 按真实链接去重，分别保存正文与公开可见数字，写入 SQLite 和断点文件。
5. 中断后从同一工作区续采；`audit` 输出每层覆盖率和缺失原因。

示例目标为“监所家属”。截至 2026-09-23 的本地 SQLite 核查：工作区有 162 条不同文章记录，其中 161 条关联当前 Mac 微信账号采集源，154 条有有效正文，161 条有阅读数。微信主页显示“301 篇原创内容”，但历史列表没有到达末尾的完成证据；转发、旧点赞、评论数和评论明细仍未形成可靠的完整采集链路。上述数目仅为本地试跑快照，不应当作全量结果。

这足以验证界面操作、账号校验、去重、正文与两项数字入库的技术链路；它不证明整个账号已经读完。

## 可复用试跑

先在微信中打开目标文章，点击公众号名称进入主页，并确认主页名称与文章作者一致。安装依赖后运行：

```bash
uv sync --extra mac --extra dev
.venv/bin/gzh-reader doctor
.venv/bin/gzh-reader collect \
  --url '<目标公众号的一篇文章链接>' \
  --account-name '<微信主页显示的名称>' \
  --max-new-articles 5 \
  --output '<数据根目录>'
```

`--max-articles` 是该工作区累计保存的文章数量上限，可省略；`--max-new-articles` 是每轮新增上限，默认 5 篇。试跑后读取 `<数据根目录>/<公众号名>/audit/coverage.json`，核对目标账号、正文和字段覆盖率。继续试跑可执行：

```bash
.venv/bin/gzh-reader resume --workspace '<数据根目录>/<公众号名>' --max-new-articles 5
.venv/bin/gzh-reader audit --workspace '<数据根目录>/<公众号名>'
.venv/bin/gzh-reader export --workspace '<数据根目录>/<公众号名>'
```

每轮最多新增 5 篇，需由用户决定是否再启动下一轮；不会自动连续跑到账号全量。运行期间需保持微信可见；工作区数据不会进入 Git 仓库。源码采用 MIT License 的独立实现，没有复制参考 Windows 项目的代码。已验证阶段的优先目标是形成可复用、可审计的样本采集流程，然后再用确定性程序执行批量循环；DeepSeek 只可选地复核公开列表 OCR 文字，不负责逐篇点击。

## 微信 4.1.x 标签页适配与失败恢复

- 新版微信将公众号主页和文章放在同一个 `微信 (窗口)` 的不同标签中。程序必须在每次点击前核对当前页面是目标账号列表，在文章打开后核对卡片标题和底部作者；标题或作者不一致不得入库。
- 主页向下滚动后，“301 篇原创内容”会折叠；此时须用顶部账号名、列表导航和阅读数共同确认主页。Vision 可能把“全部 文章”并为一行、把账号图标误识别为前缀，因此不要求 OCR 行完全相等。
- 正文里可能有“亲情邮”等小程序卡片。不要点击文章中央来聚焦复制；若出现“即将打开小程序”，只能选“取消”，不能选“允许”。正文不足以验证时保留 `missing`，不得计入新增成功。
- OCR 误读卡片标题或列表在滚动后重排时，点击可能打开另一篇文章。标题校验失败后必须关闭当前文章、重新确认目标账号列表并重新 OCR；不能直接使用上一视口的下一张卡片坐标。无法恢复主页时立即停止。
- 旧版数据使用 `human-...` 内部账号 ID，新版使用 `human:...`。断点查询按账号名称与 `mac_human_agent` 来源合并两者，避免把已完成文章重复打开；真实文章 URL 仍是稳定去重键。

以上保护已有本地单元测试；小程序弹窗和错误卡片的失败路径也在实机观察过，但长批次稳定性尚未验收。遇到连续两次文章失败、白屏、退出登录或账号身份不符，应停止该批次，不自动继续。

## 批量阶段还需解决

- Vision OCR 已移入独立子进程并设置 12 秒硬超时；超时后保留断点并输出审计。本次长批次曾在第 4 次卡片尝试后停滞，故仍需继续验证其他窗口操作是否可能卡住。
- 证明历史列表确实到达末尾；连续相同视口只能记录为未完成。
- 对正文和五项互动字段分别审计。当前桌面页面没有稳定提供所有转发、旧点赞、评论数或评论明细，缺失必须保持未知。
- 首次只粘贴一篇文章链接就自动抵达账号主页尚未实现；现阶段需要先在微信中打开主页。

批量读取的主要循环由确定性程序执行，不逐篇调用大模型。DeepSeek 是显式开启的可选 OCR 复核：仅在本地规则找不到卡片时发送公众号列表的公开 OCR 文字，最多 5 次/运行；不发送文章正文或截图。模型只返回候选行号，程序仍从原始 OCR 行验证文字、数字和坐标。未提供密钥或未勾选时不调用 API；目前已通过模拟响应测试，尚未用真实密钥发出请求。
