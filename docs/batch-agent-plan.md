# Mac 批量公众号读取与多模型 Agent 实施计划

更新：2026-09-26。本文是待实施计划，不是完成声明。

后续执行以 [execution-plan-v3.md](execution-plan-v3.md) 为准：它纳入了双供应商客户端已存在、Agent 仍有限、91 项测试和最新画面不可读的事实。本文保留为历史方案，下面的“当前起点”是较早快照。

## 目标与固定约束

交付一个可独立安装的 Mac 仓库：用户双击启动、粘贴一篇公众号文章链接、选择模型与目录，程序自动发现同账号文章、批量读取、断点续传、导出和审计。目标账号先用“监所家属”。10 篇是进入批量的验收门槛，不是产品的永久篇数限制。

采集通过真实 Mac 微信界面操作。参考 Access_wechat_article 的任务队列、可追溯记录和批量流程，独立实现 Mac 控制层。参考项目自身使用 UI、MITM 与后台 Worker 的混合架构；纯界面实现的字段范围必须单独验收。普通用户看不到的数据记录为不可见，不伪造、不从模型猜测。

用户只需要图形界面。开发和验收工具可以使用 CLI，但不能把运行终端变成日常使用前提。稳定运行仍要求微信已登录、Mac 未锁屏且目标窗口可操作；发生用户抢占鼠标/窗口时暂停并保留进度。

## 当前起点

- 已有本地 UI 控制器、SQLite、导出器、图形向导及 DeepSeek OCR 复核代码，最近 72 个测试通过。
- DeepSeek 当前是写死供应商的文字复核模块，不是通用 Agent；豆包未接入。
- 本地 162 条文章记录；43 条只通过最低正文长度检查。旧记录不能计入新的批量验收样本。
- 微信新版标签、继承滚动位置、误点小程序、页尾短文字误判已定位；部分修正尚未通过完整实机验证。
- 退出登录的确定原因和有效解决方法尚未找到。不能用“未再次遇到”证明问题消失。

## 低成本模型也能执行的结构

```text
图形向导 / Codex / DeepSeek Agent / 豆包 Agent
                   ↓ 统一的有限工具协议
任务队列 + 状态机 + 参数与身份校验 + 重试预算
                   ↓ 本地 Mac 操作工具
微信页面 → 可见证据 → 分层保存 → 校验 → 断点 → 导出
```

让模型每次只处理一件小事：从当前识别出的候选文章中选一个，判断一种页面状态，或选择一个允许的恢复动作。坐标计算、窗口定位、滚动、保存、去重和下一步合法性由程序负责。模型无须记住长期历史，重启后从 SQLite 恢复。

提供两种运行方式，使用相同执行器：

1. 固定流程自动运行，识别不清时才询问模型，适合最低消耗批量。
2. Agent 按工具调用逐步调度，适合 Codex、DeepSeek、豆包接入与诊断。工具调用结果返回新状态、证据引用及下一步允许动作；执行器拒绝非法调用。

原生 Computer Use 能力不是基础要求。纯文字模型通过 OCR 结果和工具协议工作；支持视觉的具体模型可选择接收仅含目标文章区域的截图。模型的视觉和工具能力分别检测，不能以品牌名称推断。豆包首先指火山方舟 API 模型，不能把豆包聊天应用会员当成 API 授权，也不能假设远端 Agent 可以直接控制这台 Mac。

## 必须落实的错误防护

| 历史故障 | 程序责任 | 验收证据 |
| --- | --- | --- |
| 打开成其他账号/文章 | 固定任务账号，核对文章标题、账号和真实 URL；冲突进入待复核 | 跨账号、同名标题样本必须拒绝错误归属 |
| 旧坐标点进小程序 | 坐标绑定当前窗口、视口版本和候选卡片 ID；页面变化立即作废 | 旧视口动作被拒绝；弹窗只允许可确认的取消或暂停 |
| 微信升级、分离/合并窗口 | 分离布局适配器，运行前检测版本与实际窗口布局 | 不支持的布局给出中文诊断；不会盲点 |
| 沿用上一篇滚动位置 | 文章打开后核对当前标签，再回到顶部读取；页尾单独判断 | 从顶部、中部、底部起始均能读取或明确停止 |
| URL 被当正文 | 校验正文与标题、账号、首尾证据；区分最低长度通过与完整性已核验 | URL-only、旧剪贴板、推荐卡片内容不能标为完整 |
| 页尾失败连正文也丢失 | 先校验身份，分阶段保存；身份未确定时只存待核对记录 | 指标失败后已核验正文保留，缺失可单独重试 |
| 断点重复打开旧文章 | 合并内部账号别名须有身份依据；URL 为最终去重依据 | 重启后已成功正文不重复采集；标题只是导航线索 |
| 退出账号/窗口消失 | 分类记录服务端退出提示、进程崩溃、窗口关闭、普通加载超时 | 故障前后有动作时间与进程/页面证据，不能只写“风控” |
| 字段覆盖被旧快照抬高 | 指标按最新快照逐字段计数，保留旧快照供查证 | 缺失不补零；“1万+”保留原显示及范围，不能变精确值 |
| 无限卡住或反复点击 | 每个动作有截止时间与有限恢复次数，重复无进展触发暂停 | 在故障注入下有界停止且断点可恢复 |

## 按顺序执行的工作包

### P0：建立可回放的基准和验收清单

产物：`tests/fixtures/ui/` 的脱敏页面状态、失败动作轨迹；`docs/acceptance/` 的单篇和批量验收表。先保留现有原型，不进行无边界重写。

收集文章正常页面、页面在底部、合并/分离布局、加载中、小程序弹窗、登录失效、标题相似、URL-only 剪贴板等样本。旧截图不再作为点击坐标依据。保留测试缺口记录，不用伪造样本冒充实机事实。

通过条件：每个历史故障至少对应一个可检测状态或明确的待取证项。

### P1：做稳单篇执行器与分层保存（优先级最高）

把 `human_agent.py` 中观察、窗口控制、采集和调度逐步拆到 `ui/observer.py`、`ui/controller.py`、`ui/layouts.py`、`workflow.py`；复用现有已测试函数，逐步替换调用，保留兼容入口。

状态顺序：主页已验证 → 卡片已识别 → 文章已打开 → 身份已确认 → 正文已保存 → 可见指标/评论已保存或注明缺失 → 返回主页已验证。

基础工具：`observe`、`list_candidates`、`open_article(candidate_id, observation_id)`、`read_article`、`read_visible_interactions`、`return_to_profile`、`scroll_list(observation_id)`、`pause`。模型不直接调用任意坐标、快捷键或 shell。控制器在执行前重新确认前置条件；改变界面的工具串行执行。

每次工具返回：`state`、`observation_id`、`allowed_actions`、`evidence_refs`、`error_code`、`retryable`。正文、指标、评论的失败分别入库；任务状态不能混用作文章完整性状态。

通过条件：实机完整走完一篇，并覆盖滚动位置和小程序弹窗恢复；与原页面核对链接、账号、正文首尾、可见数字。遇到身份不明直接暂停。

### P2：统一 DeepSeek / 豆包接口，并提供 Agent 调度

新增 `models/base.py`、`models/deepseek.py`、`models/ark.py`、`agent_runtime.py`、`tool_schema.py`。把现有 OCR 复核迁移为通用能力；保留旧 DeepSeek 配置兼容。

配置字段：provider、base_url、model_id、api_key、超时、调用与 token 预算。模型 ID 可配置；不硬编码某个品牌永远支持视觉、JSON 或某一种思考参数。供应商特有参数由适配器处理。

优先使用工具调用；对只支持文字 JSON 的模型，使用同一动作 schema，并严格验证 JSON、枚举、候选 ID 和状态。无效输出最多允许一次格式修正；仍失败则按已验证固定规则处理或暂停。工具错误必须如实回传，不能让模型宣称保存成功。

连接测试分为认证、工具/JSON 格式、可选视觉；不能仅收到 `ok` 就宣称可驱动采集。提供模拟模型测试、供应商接口测试和实机小样本测试三层结果。真实 API 测试需要用户在本地向导输入各自密钥；未提供时只标“适配器已测试，真实连接未验证”。

通过条件：DeepSeek 与豆包各通过同一组状态/工具协议测试，能分别从断点接续同一个任务；模型替换无需改采集器。正文和账号凭据默认不发模型，目标区域截图是单独可选项。

### P3：10 篇跨视口与续传验收

按 1 → 3 → 10 篇递增验证，10 篇须跨至少 2 个列表视口，排除旧验收记录。对每篇核对身份、URL、正文首尾和可见指标；公开评论开启且存在时另选样本验证评论与回复。未见到评论样本就明确记“未验收”。

中途暂停、重启、切换模型，确认正文去重、指标新增快照与缺失项重试。测量新保存数、重复打开数、失败动作、总耗时和 API 消耗，不能只展示“已运行”。

通过条件：10 篇可核对，续传不重复下载成功正文，期间无退出/崩溃；这只证明此样本通过，不证明以后永不退出。

### P4：实现真正的批量任务

新增 `scheduler.py`。总体数量可设指定篇数或“直到列表末尾”，内部小批次按队列持续推进，检查点落盘后自动继续；每轮 5 篇仅是初始测试设置，不是永久限制，也不宣称安全阈值。

先验证超过历史约 30 篇故障点的累计任务，再扩到更大样本。节奏由配置和实际错误反馈控制，不用随机点击或设备/IP 轮换。无法判定页面有进展则暂停；无法证明列表末尾时标为 `list_incomplete`。

为退出问题安排逐动作实验：观察 → 打开一篇 → 复制 → 滚动 → 关标签 → 下一篇，每次只增加一个环节。结合进程与界面证据定位；一旦出现明确退出或崩溃停止本轮，下一次从有效断点恢复，不能自动重新登录反复冲撞。

通过条件：批量到达设定数量或有证据的列表末尾，能跨程序重启续采，所有失败有明确位置；对整个账号枚举是否完整单独给出结论。

### P5：图形界面、外部 Agent 接口与 GitHub 交付

向导：粘贴链接 → 自动核对账号 → 选择“固定流程 / DeepSeek / 豆包 / 自定义兼容接口” → 输入本地密钥和读取范围 → 开始/暂停/继续 → 查看结果。

固定流程可不配置模型；Agent 模式提供相同工具的本地接口，再封装 MCP 供 Codex 或其他支持 MCP 的宿主接入。宿主和 API 模型是不同层：只支持模型 API 的客户端仍需本仓库的 Agent runtime 执行工具。

把 macOS 辅助功能/屏幕录制权限和微信窗口要求做成可验证的中文向导。模型密钥不进入日志或仓库。导出正文、逐字段指标快照、评论、缺失清单、SHA-256 校验和及验收记录；不把用户文章正文和聊天截图提交到公共仓库。

通过条件：干净 Mac 双击安装启动并完成小样本；GitHub 有测试、安装说明、模型接入说明、界面适配说明、已验证范围与已知限制。批量实机通过后才标为可复用版本。

## 交给低成本开发模型时的任务模板

每次只领取一个工作包中的一个可测试变更。任务必须包含：目标文件、前置状态、失败样本、允许修改范围、期望行为、验证命令与验收条件。不得靠整段聊天历史恢复要求。

执行顺序固定：读取本文及相关代码 → 重现单个失败 → 最小修改 → 运行相关测试 → 检查 diff → 更新进度和实机验证状态。测试通过但没有实机证据时，状态只能是“待实机验收”。不得自动发布、替换数据、重置用户改动或因为调用预算用尽把任务标完成。
